We’re happy to share that JetBrains has renewed its Platinum sponsorship of the Godot Foundation for 2027. JetBrains [first joined as a Platinum sponsor](https://godotengine.org/article/jetbrains-joins-dev-fund-supports-godot/) in August 2025.

Alongside the sponsorship, JetBrains has kept expanding Godot support in JetBrains Rider. Over the past year, Rider has grown to cover GDScript, C\#, and C++ GDExtensions in one IDE, and it’s [free for non-commercial use](https://www.jetbrains.com/non-commercial/), including hobby projects, learning, open-source, and content creation.

Here’s what Rider brings to Godot developers:

* GDScript support: Code completion, *Find Usages*, the *Rename* refactoring, inspections, and a formatter. You can drag nodes from *Scene Preview* into a script to insert their paths or generate `@onready` and `@export` variables.  
* Debugging and testing: Debug GDScript and C\# from Rider, including specific scenes and tool scripts, and debug both languages at the same time in mixed projects. C\# tests run with the Chickensoft GoDotTest runner.  
* Native development: Build C++ GDExtensions with CMake, and inspect Godot’s native types in the debugger with godot-cpp.natvis on Linux and macOS.  
* Addon development: Project templates for Godot games, assets, and editor plugins, ready for publishing on the Godot Asset Store.  
* Coming in Rider 2026.3: Navigation from `$Node` and `%UniqueNode` references to scene nodes, *Find Usages* for signal connections made through Callable, and the *Remote Scene* tree and node inspector while debugging C\#. These are available now in the [Early Access Program](https://www.jetbrains.com/rider/nextversion/).

For the full overview, including how Mega Crit develops Slay the Spire 2 with Rider, read the JetBrains blog post: [From GDScript to GDExtensions: One IDE for Your Godot Code](https://blog.jetbrains.com/dotnet/2026/10/29/from-gdscript-to-gdextensions-one-ide-for-your-godot-code/).

### About JetBrains Rider and Godot

JetBrains has been investing in Godot support for several years. Rider provides code insight and debugging for GDScript and C\#, scene and resource navigation, and C++ tooling for GDExtensions and engine work. The official [JetBrains Rider Integration](https://store.godotengine.org/asset/jetbrains/jetbrains-rider-integration/) addon in the Godot Asset Store connects Rider to the Godot editor as an external editor.

JetBrains also contributes to the engine itself. An [upstream contribution](https://github.com/godotengine/godot/pull/109637) from Rider developer Ivan Šachov, merged in October 2025, extended Godot’s Debug Adapter Protocol support with scene selection and command-line arguments so other external tools can build on it, too.

We’re glad to see that JetBrains’ support goes hand in hand with tools that make working on Godot projects easier for everyone.
